# CONTOSO ENTERPRISE ENABLEMENT — STYLE GUIDE
## One page. This is all of it.

*Fictional style guide for a fictional company. See `../DISCLAIMER.md`.*

---

## The rule everything else serves

**Write for the person who has to act, not for the person who approved the project.**

---

## Structure

| Rule | |
|---|---|
| **Lead with the outcome** | What this does for the reader, in the first two lines. Never open with what a thing *is*. |
| **One task per piece** | If it needs two, write two. |
| **Prerequisites go first** | Anything needed before step 1 appears before step 1. Always. |
| **Show the success state** | The reader must be able to tell whether it worked. |
| **Name the failure path** | What to do when it doesn't work, and who to actually contact. Never "your IT admin" unless the audience has one. |

## Voice

| Do | Don't |
|---|---|
| Second person — *you* | Third person — *the user* |
| Active voice | Passive voice |
| Short sentences | Sentences with three clauses |
| Plain verbs — *turn on*, *open*, *ask* | Enable · activate · provision · leverage · utilise |
| Say the limitation plainly | Bury it, or omit it |

## By genre

| Genre | Register | The trap |
|---|---|---|
| **Learn unit** | Instructional, warm, second person | Explaining before instructing |
| **How-to / docs** | Neutral, procedural, no enthusiasm | Tone drift into marketing |
| **Blog / announcement** | Energetic is permitted | Energy substituting for substance |
| **Executive summary** | Decision-first, evidence-backed | Recommending without naming an owner |
| **Quickstart / lab** | Numbered, sequential, testable | Step order that doesn't survive a real run |

## Claims

| | |
|---|---|
| **Every capability claim must be true today** | Not announced, not planned, not in preview unless labelled |
| **No version numbers, SKUs, or interface paths** | They age the content out within a quarter |
| **Attribute anything contested** | Name the owner, the system, or the source |
| **Say what you don't know** | *"We don't have a control for this yet"* is a stronger sentence than a confident guess |

## Audience

| | |
|---|---|
| **Write to one card** | Content written for everyone works for no one |
| **Match the access the reader actually has** | Never instruct someone to do what their permissions forbid |
| **Match the time the reader actually has** | Length is an audience decision, not a completeness decision |
| **Use their words** | Each card carries a vocabulary table. Use it. |
| **Assume their expertise** | Explaining what they already know reads as condescension |

## Accessibility and plain language

| | |
|---|---|
| Avoid idioms, metaphors, and wordplay | Many readers are reading in a second language |
| Expand an acronym on first use — unless the card says assume it | |
| Don't rely on colour, position, or a screenshot to carry meaning | |
| Front-load the sentence | The important half comes first |

## Never

| | |
|---|---|
| ❌ *"Simply"*, *"just"*, *"easy"* | If it were, they wouldn't be reading |
| ❌ *"Always review the output"* offered as a control | That's a hope, not a control |
| ❌ Prerequisites discovered mid-procedure | |
| ❌ A capability claim with nothing behind it | |
| ❌ Telling a reader to contact a role that doesn't exist in their org | |
